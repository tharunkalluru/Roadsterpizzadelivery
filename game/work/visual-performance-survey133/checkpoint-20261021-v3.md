## Evidence-led algorithms

The untouched v2 baseline had 5,896/6,002 scene nodes at low/standard spawn. An analytical read of the actual runtime inputs identified **82 scheduled trains**, retaining 1,804 nodes and 1,476 meshes, plus **176 signal heads**, retaining 1,056 nodes and 528 separate lamp materials. Three.js updates invisible descendants' matrices; setting `visible=false` did not remove those transforms. The low CPU profile's largest non-idle rendering self samples included `updateMatrixWorld`, `projectObject` and `applyCull`. This justified changing scene representation rather than lowering visual quality.

1. **Visible train allocation with a bounded reserve.** All timetable descriptors remain. Only services inside the original strict 700 m low / 1,400 m standard-high visibility radius acquire a three-coach hierarchy. Inactive/distant trains detach; up to four unused rigs are retained for reuse. This is an idle reserve limit, never a cap on visible trains. Releases occur before acquisitions to reuse rigs on camera jumps. Every reused coach and door is fully positioned before attachment. Four rigid parts per coach cache their local matrices while retaining world updates; sliding doors remain dynamic. Geometry, materials, visibility thresholds, headway, dwell, sound and pose formulas are unchanged. Disposal is idempotent.
2. **Spatial signal instancing and state-change updates.** Original pole, housing and lamp geometry is represented by 41 actual-world tiles of 128 m, 328 mesh objects and seven shared materials (one housing material plus three lamp colours at two intensities). Tile-local instance coordinates limit Float32 quantization. SignalSystem still decides each head's exact colour and tick. Only changed tiles rebuild lamp membership; bounds are recomputed for empty/nonempty transitions. Fixed tile transforms are frozen after final scene attachment. Replacement/view cleanup disposes instance buffers and owned geometry/materials exactly once.

The rendering techniques follow the general batching/resource reuse guidance in [MDN WebGL best practices](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices); the installed Three.js 0.186.1 implementation is the API authority. No dependencies, shaders, textures, visual LOD, source identity or graphics quality settings changed.
