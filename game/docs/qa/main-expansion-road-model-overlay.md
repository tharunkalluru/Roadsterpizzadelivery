The common modeled-road path is implemented but currently has no generated geometry block, so experimental XY geometry is not installed in production. `applyVerifiedRoadModel(core)` runs at the start of `World`, after generic or cached road grading and before ordinary underpass, stadium, construction and railway conditioning. It validates every expected road and modeled node before changing anything. Changed IDs/endpoints, a missing incident road, an invalid profile or displacement beyond 5 m retains the generic core with a mismatch report.

The overlay retains exact source road IDs, from/to nodes and travel direction. Source-arclength bindings transport the existing kerb stops to the corresponding modeled point while preserving their lateral offset. Source road objects, packs and node tables remain immutable. The ordinary conditioned-world profile pass then installs the final verified linear heights; those arrays are not Hermite-resampled afterward.

`applyVerifiedRoadTileGeometry(zone)` is the shared owner/context path. The worker enables it only after the core overlay reports active, applies final core patches, then applies the separately source-bound tile-only roads and the same modeled node table before construction/rendering. Tile-only IDs never enter the raw-core prepared-cache payload. A tile source mismatch fails that tile build instead of emitting a disconnected street.

The generated correction file will contain an optional `geometry` block and the final `conditionedWorld` profiles. Geometry expectations come from the generic `prepareRoadGrades(..., true, false)` model. The generator atomically removes the older two Tarnaka `roadGrades` profiles only when both IDs occur in the replacing conditioned solution. The final runtime/cache preparation therefore has the same generic input as the geometry binding. Full verification checks this order explicitly; generation never derives the generic input from its own earlier corrections.

Final generation uses `scripts/generate-road-profile-corrections.mjs --stage conditionedWorld --solution FILE --input-model CONDITIONED --geometry-model PRECONDITIONING --geometry-source GENERIC-GRADES --tile-transports SUPPLEMENT`. The tile supplement must directly bind that conditioned input. The source model, solver, decoded raw packs and runtime/generator inputs remain fingerprinted. The full verifier exercises the common core overlay, ordinary conditioning, conditioned profiles, final worker patches and every bound tile owner/context pack.

`scenerySource` retains the original prepared XY/Y/width corridor alongside modeled pavement only for building, pier and fixed roadside exclusion. It supplies no old asphalt, invisible support or graph edge. The field survives profile matching, current/changed worker patches and strict cache serialization.

Four focused groups pass for atomic/source/incident/displacement failures, stop/node/graph coherence, owner/context application and cache-versus-generic overlay parity. Active-data whole-city parity, emitted physical geometry, final real-input drives and publication remain open until the offline model is feasible and held.
