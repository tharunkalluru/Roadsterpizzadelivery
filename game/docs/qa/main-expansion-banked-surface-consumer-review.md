# Local apron crossfall: consumer audit

Read-only source review, 2026-11-03. No production changes, runtime candidate, UI operations, or release approval. File/line anchors describe the current working tree on `codex/story-realism-main`; neighboring work may move them.

The existing finite triangle support is sufficient to represent a banked road. The blockers are the absent model/patch contract and consumers that independently reconstruct a flat cross-section. A feasible LP alone would not establish driving/render agreement.

## Geometry contract to settle first

- `src/world/types.ts:2-8`, `src/world/bridge-clearance.ts:12-24`: there is currently no bank schema. The architect's current basis is **one signed gradient per control cross-section**, with `L.y = C.y + b * distance(L,C)` and `R.y = C.y - b * distance(R,C)`, `|b| <= .025`, edge grades at most `.1`, and `|delta b|/delta s <= .001`. This is not two independent side rises or a crown.
- Preserve the exact triangle diagonal used by the LP (`0,1,2` and `0,2,3`) and its actual pavement widths/auxiliary lanes. On a curved or changing-bank quad, a separate analytic `centrelineY + lateral*b` query can disagree with those triangles. Use a common finite triangle evaluator for lane/prop heights.
- Source control heights `C_i.y` can remain fixed while the existing across-width diagonal changes interpolated `C(s)` between controls. The architect reports a small example deviation, not a global guarantee. Root must distinguish fixed control heights from strict fixed centreline interpolation. Strict `C(s)` requires centreline-split strips and **regenerating LP coefficients**. Do not silently change the mesh basis after solving.
- If independent side gradients/crown are later requested, one across-width quad cannot preserve the centreline hinge; that is a separate topology change. `quads[i]` currently means one source segment in paint/clearance consumers, so splitting requires explicit source-segment metadata rather than changing list indexing by accident.
- Any <=5 m XY repair must be a derived, coherent junction repair: all eligible incident endpoints/context copies and the model node agree. Keep raw source packs/coordinates immutable and record displacement/provenance. `RoadGraph` derives node positions from the first edge endpoint (`src/game/roadgraph.ts:61-62`); city junction/merge consumers also read `zone.nodes` (`src/world/city.ts:625`, `649`). Updating only one edge is insufficient.

## Already generic; do not rewrite unnecessarily

- `src/world/road-surface.ts:5-26`, `52-59`: arbitrary vertex Ys and the existing triangle diagonal already work; tile clipping interpolates the original triangle planes.
- `src/world/city.ts:48`, `305-311`: `Surface.roadQuad` can carry banked triangles. `ya/yb` remain useful metadata/broad-phase values but must not replace exact height when a quad is available.
- `src/game/physics.ts:17-40`, `65-80`: `supportAt` and `roofUnder` use exact finite `roadQuadHeight`; reachable-layer selection and finite end behavior should remain intact. Banking does not justify loosening the 1.6 m reach, .01 m overlap tie, or continuous-road rules.
- `src/world/bridge-clearance.ts:33-73`: bridge boundary clipping already solves actual triangle planes. It needs banked input quads and correct boundary edge Ys, not a new tolerance.
- `src/game/jump-motion.ts:27-39`, `src/game/spatial-safety.ts:35-40`, `src/delivery/systems/pickup-clearance.ts:14-16`: exact quad consumers inherit banked heights. Preserve flight/jump/interior clearance semantics; add regression evidence rather than alternate surface formulas.

## Conditional adjacent consumers

- Walkers: `WalkPath` is XZ-only (`src/world/city.ts:106`; creation at `540`, `556`, `1052`), and `src/game/walkers.ts:115` fixes feet near Y=0. A banked ground apron/XY repair intersecting a walking path needs path/foot surface elevation and crossing contact. Elevated road banks with no walking paths do not require a wholesale walker rewrite.
- Metro ground access: `src/world/metro-station-access.ts:55`, `60-68`, `133-140` assumes street Y=.12/0. Its clearance is supplied through centreline-based `roadStructureClearance` (`src/world/city.ts:1448-1458`; `src/world/structure-clearance.ts:51-80`). If a proposed bank/XY repair reaches an entrance/foot/lift approach, refit/check the actual ground connection and banked finite headroom; preserve actual upper station pads and physical entry. If all candidate changes are disjoint, record that fact and keep the accepted metro model.
- Structural/building/rail checks: `src/world/structure-clearance.ts:60-80`, `src/world/building-clearance.ts:82-98`, `src/world/railway-road-clearance.ts:13-22` use scalar centreline height. For changed footprints, use finite banked height extrema at intersections/footprints so an up-bank edge cannot lose protected clearance. Existing conservative scenery widths and real rail/ORR/survey controls remain.
