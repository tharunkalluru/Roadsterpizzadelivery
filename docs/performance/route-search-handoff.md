# Cooperative route-search handoff

Production source is frozen for coordinator integration. Ownership changes are limited to `src/game/roadgraph.ts`, `src/game/route-search-gate.ts` and the `Game.updateRoute` function. No player, route geometry, smoothing, ribbon width, road legality, collision or source-map coordinates changed.

The actual 52,412-edge permanent core graph confirmed that search itself is expensive: the initial six-query, three-run search-only probe measured 0.74–18.82 ms unthrottled in Node. This justifies splitting search even though the browser's recorded routing phase also includes guidance generation.

`RoadGraph.routeJob(...routeArguments)` creates lazy work. `RoadRouteJob.step(1)` advances it toward a one-millisecond elapsed-work target; it reports pending, complete, cancelled or invalidated and never exposes partial results. Scans for start/destination roads and fallback nodes, heap expansion/relaxation, predecessor reconstruction, path point assembly and distance accumulation yield cooperatively. Jobs reject a changed graph revision before resuming. `cancel()` releases the generator. Individual primitive operations, garbage collection and host scheduling can overrun a slice, so the budget is a target rather than a hard JavaScript preemption guarantee.

`RoadGraph.route()` retains its public synchronous API and drains the exact same work to completion. The frozen pre-change algorithm in `tests/fixtures/sim-route-legacy.ts` is an independent oracle. Six focused tests cover 160 directed/stacked randomized exact route comparisons; lazy operation limits; explicit cancellation; graph/target/placement/mode invalidation; failed-result retry delay; and shared presentation-frame scheduling.

`RouteSearchGate.updateSearch()` owns the unique pending generation and coalesces retries. Target identity includes the selected area and coordinates. Graph revision, placement revision or airborne mode changes cancel old work before publication. Several fixed simulation ticks sharing one renderer frame share one millisecond of search allowance. The gate accumulates actual sampled player travel while a job is pending; completed paths can be advanced by that travel plus the ordinary small per-step allowance. Publication still checks current road identity, lateral error and vertical level. This prevents both stale paths starting tens of metres behind the car and unsafe jumps to a nearby overpass/hairpin arm.

An actual `Game.updateRoute` test delays a real route job for 50 ticks while the fixture car advances 50 m. The valid old route remains available, the completed replacement starts at the current position, only one search is launched, and a subsequent graph change cancels pending work without discarding valid existing guidance. Grounded refreshes and the four-second coarse flight overview now use this same gate; neither path invokes a full synchronous search.

The reproducible real-core diagnostic (`node scripts/route-search-benchmark.mjs`) runs six route queries in three alternating-order pairs. It recorded 36 exact output comparisons with zero mismatches. Every point, length, completion flag and edge ID matched the frozen reference. Cooperative slice median was 1.0008 ms, MAD 0.0013 ms and maximum 1.8155 ms; all raw slices are retained in `route-search-probe-after.json`.

The synchronous generator wrapper has measurable overhead: the same diagnostic's aggregate legacy median was 4.4396 ms versus 6.8211 ms for the generator drain. These routes differ in length, so this aggregate is diagnostic rather than a whole-game percentage comparison. `makeOffer()` and the initial offer approach estimate still use synchronous `graph.route()` for compatibility. They can produce order-generation latency and are not claimed to have a one-millisecond budget. Normal grounded and airborne route refreshes use the cooperative API. Guidance smoothing/clearance/ribbon construction remains synchronous and unchanged; a new browser profile must distinguish its cost from the now-sliced search before declaring the entire routing phase bounded.

Validation at freeze: six focused route tests, TypeScript and diff checks passed. The full suite passed 88/88 immediately before adding the final extra actual-Game graph-cancellation assertions; the focused suite passed afterward. The coordinator owns the final complete suite, build and visible gameplay regression. Node timings are not calibrated browser, phone, GPU or sustained-FPS evidence.
