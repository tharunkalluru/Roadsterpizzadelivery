# World optimization implementation handoff

Implemented in `src/world/world.ts`, `tileworker.ts`, `city.ts`, new `streaming-utils.ts`, and `tests/world-streaming.test.ts`. No commits or publication performed by this agent.

## Integration

- `world.pumpJobs(budgetMs = 1.5)` can run before inactive/paused returns. An internal scheduled RAF also completes loading without input. Calls close together share their allowance to avoid double pumping.
- `world.setStreamFocus({ x,z,vx,vz,mode,landingBounds?,pinnedTileKeys? })` supplies predictive velocity and landing coverage. Modes: `road`, `jump`, `flight`, `descending`.
- `world.setPinnedRoadIds(traffic.retainedEdges().values mapped to edge.e.id)` protects tiles needed by active jump interactions. Alternatively `pinTiles(token,keys)` and `releasePin(token)`.
- `world.nearbyLamps(x,z,r = 70)` uses the tile-owned 100 m lamp grid.
- `world.updateVisualDetail(camera, player.pos)` updates tree detail at most four times per second. Trees within 180 m always keep original detail. Far geometry enters below 6 projected CSS pixels and exits above 9 pixels. Matrices/colors/buffers are retained; only changed membership uploads.
- `world.prepareMesh?: (mesh: THREE.Mesh) => void` is an optional synchronous property and constructor option. The coordinator assigns the Engine public-renderer warm-up hook before loading. It runs once per new ground/buffer/near-and-far instance/signal source mesh as a separately yielded job before publication. Skyline preparation uses separate creation/warm-up queue jobs. It does not put `ensure` behind an asynchronous shader wait.
- `world.revision` changes on active tile publication/removal. `world.streamStats` exposes staged/active/retiring/skyline estimated bytes, worker decoded-cache estimate, job count, maximum job/activation time and admission failures.

## Enabled behavior

Worker-built merged buffers are prebounded and split at 48,000 vertices (triangle aligned), balancing first-use upload size against draw calls. Main-thread mesh/metadata creation uses generators under the shared allowance. Tile-owned read-through collision grids attach/detach in constant owner operations and cache queried cells; metadata/graph/visual publication remains in one JavaScript turn. The loading/relocation pump does not advance simulation time. GPU geometry disposal is deferred in small jobs and retiring bytes stay counted until disposal completes.

Full-tile admission estimates retained CPU plus GPU vertex data and instance data. Defaults: 256 MiB Low / 384 MiB High active budget, 96 MiB staging cap, 96 MiB bounded relocation overlap. Rejected required coverage enters the existing bounded failure/retry path while retaining current support/old area. These limits are implementation defaults that need dense-city measurement; they are not detected free phone RAM. Worker decoded packs have a six-entry and estimated 96 MiB LRU bound.

QA correction: `ensure` now explicitly registers required target keys and a 350 m old-player support ring. Requests/install prioritize those keys; optional background tiles cannot consume relocation slots. Pending builds reserve estimated bytes before dispatch. Temporary capacity pressure defers work without poisoning loader failures; optional rejection is not a network failure. Near/ahead pressure can retire unpinned outer optional tiles while keeping current support, jump pins and required target data. An individual tile known to exceed staging capacity fails explicitly; impossible aggregate working sets retain the bounded ensure timeout. Root reduced initial relocation preparation to the essential 650 m ring instead of requiring the full High streaming radius, which had exceeded the fixed budget in Android QA. No memory limits were raised.

Velocity lookahead supplements the surrounding radius; landing regions receive detailed coverage. Flight requests a separately bounded, visual-only skyline from actual source building footprints and heights when detailed work is idle. Its 32 MiB estimate cap and distant eviction keep it bounded. The skyline never enters collision/support grids, is hidden where full detail is active, and is hidden on returning to road mode.

Dense repeated tree components use local shared-template instancing (groups of at least 24). Small groups retain the previous merged geometry. Near templates are the exact original `cyl6`/`ico0`; far trees use a three-sided trunk and octahedron crown only below the projected-size threshold. Critical roads/buildings/landmarks and all collision geometry remain independent of this visual detail policy.

Further P10 implementation restores minor-road lane markings independently of Low. Building parapets and rooftop decorative rooms/rebar now use separate 200 m cosmetic batches generated in both presets. Repeated black rooftop water tanks share exact `cyl6` instance geometry. Cosmetic batches remain visible within 180 m of the player and otherwise use projected-size hysteresis (show above 2 CSS pixels; hide below 1.25). Their geometry bytes are included in normal tile admission, and visibility never changes support/collision grids. Named shop boards, destination/landmark models and metro nameboard/bench geometry were already independent of the legacy Low omission rules.

Real-source `0_0` Node worker comparison is in `world-real-tile-comparison.json`. Final cosmetic restoration has 13.98 MB raw vertex buffers versus 9.74 MB before restoring detail, plus 72 KB instance data. This is a deliberate quality restoration cost, not a demonstrated FPS gain. Batching at 200 m reduced the additional-detail buffer count from 240 in the first 100 m trial to 72 after roof-tank instancing. Measure actual production draw count/frame impact before final acceptance.

Building-ID publication now uses immutable tile-owned value directories prepared incrementally. Activation/removal attaches/detaches the directory instead of synchronously copying thousands of IDs or scanning neighbor buildings. Shared-border lookup ownership has its own behavioral regression test.

## Remaining measurement and scope limits

`onTileAdded` still invokes the existing graph/signal registration synchronously. Sign registration and some aggregate arrays also publish synchronously. `activationMaxMs` includes that callback and must be measured in dense scenes; do not claim every publication is under 1.5 ms merely because mesh jobs are budgeted.

First-use base geometry uploads can now be prepared through the coordinator's synchronous public renderer hook, one bounded source mesh per yielded job. The coordinator uses an ordinary warm-up Mesh sharing the source geometry and a 1×1 target; this prepares base attributes but does not pre-upload InstancedMesh-only matrix/color attributes. Source instance buffers remain explicitly owned and disposed via `mesh.dispose()` on retirement and cancellation. Record first-visible-use GPU/frame spikes and the hook's job cost; the 48k vertex limit may still need tuning against draw-call inflation. No renderer-private API or blocking GPU readback is introduced by the world hook.

Tree, rooftop cosmetic and parapet screen-size policies are implemented. General primary building/landmark mesh simplification and restoration of every cosmetic detail suppressed globally by historical Low remain outside this safe slice. Collision-bearing compound walls/curbs were deliberately not restored as cullable cosmetics. Do not describe this implementation as exhaustive city LOD.

Estimated byte counters are not total browser/GPU memory. Skyline materials use actual source colors where available and conservative fallback colors otherwise; generic skyline massing is not a bespoke distant model of every landmark. Preserve existing full landmark models nearby.

Ready for coordinator production QA; freeze world files unless a concrete test failure requires correction.

## Final missing-physics boundary correction

The final audit found that ordinary movement previously called only asynchronous `city.update`; it did not stop physics if a known manifest tile still had no coherent rendering/support after a delayed or failed stream request. `supportAt` would otherwise fall back to ground in that absent tile. This was a source-level gap, rather than a claimed reproduced visual bug.

`src/game/streaming-boundary.ts` now checks only the current 5 m body envelope and 150 ms predicted movement against `packOf`, committed `tiles` and acknowledged `empty` cells. Ready cells and unmapped cells take the synchronous fast path; the wider asynchronous prefetch policy is unchanged. `Game` checks before frame stepping and again before each simulation step. Missing essential coverage freezes input, physics, rail/traffic movement, delivery heat/time and city time at the current pose behind the opaque loader, retaining current tile and interaction pins. The existing loading pump continues. Recovery requires `ensure` followed by `engine.prepareFrame`; failed recovery offers Retry for the exact same envelope. Valid explicit relocation aborts the old recovery and its retry button, and stale completion cannot uncover a newer loader. Offer wall-clock delay is offset by the frozen interval.

`loadingRetry` accepts an optional AbortSignal solely to remove a superseded retry button and release its listener. Seven focused `game-` lifecycle/boundary tests and full TypeScript passed after this correction. New tests cover ready/unmapped/known-empty fast paths, delayed support plus view readiness, 100 frozen attempted simulation steps, blocked queued input, failed retry retaining position/order/current support, and cancellation by a valid explicit relocation. A new production build and visible delayed/offline-boundary regression remain coordinator-owned; earlier runtime metrics must not be silently attributed to this later source change.

## Pedestrian geometry ownership correction

The follow-up ownership audit confirmed an independent long-run GPU leak path in `people.ts`: the appearance cache previously called `cache.clear()` beyond 400 entries without disposing any uploaded body/leg geometry, while retired walker groups only detached from the scene. The random appearance space is much larger than 400. Current renderer count growth also includes legitimate warming, so this source defect does not imply every observed increment was a leak.

The cache now returns reference-counted geometry leases with an idempotent `release()`. Exact body/leg generation, appearance keys, colors and transforms are unchanged. Unused appearances use an LRU bounded to 128 entries and 16 MiB estimated CPU-plus-GPU attribute bytes; an active shared figure is never evicted. `Walkers` releases on actual group removal, covering relocation's direct parent removal, distance retirement and path unload. `BusPassengerExchange` releases its four leases when the exchange group is removed. `MetroStationLife` intentionally retains at most 72 shared appearance leases for its lifetime and has idempotent owner disposal for those leases, seated-leg geometry and active waiting batches. No Game behavior change was needed for those removal paths. `g.walkers.geometryStats` exposes active/unused counts and bytes plus created/disposed appearance counts.

Four new `person-geometry-lifetime` behavioral tests passed: original body attributes match exactly; shared live geometry survives another owner's release; 420 retired variants emit disposal events while respecting unused bounds; actual walker/path/exchange removal and finite station-owner teardown release correctly. Full TypeScript and diff checks also passed. Production post-cache-fix resource plateau and gameplay validation remain coordinator-owned.

The earlier read-only `refresh-resource-inventory.txt` had 1156 renderer geometries versus 1066 unique scene geometries, leaving 90 uploaded off-scene objects. That difference alone is not a leak: 31 retained bus services can own 62 decal geometries, with additional detached shared traffic prototypes, person appearances and rail/metro templates. World tile and SignalLights resources have explicit retirement disposal; rail/metro template sets are shared and finite; sign-buffer replacement disposes its old buffer. A full owner-union inventory and settled post-warmup observations are needed before claiming that all GPU resources plateau.
